# DSH voice assistant (development)

This incomplete development package is for an independent DSH assistant GUI. The DSH native Session owns model calls, tools and durable events. The shared voice interaction owns listening and playback; optional pet views must subscribe to the same owner. Remote connectivity is outside this package.

The development client registers a standalone DSH assistant entry in the sidebar panel navigation and uses one native Session and one shared voice owner. The user selects an existing assistant preset; the Session owns model calls, tools, logs and admission receipts. Capture uses `dsh-speech-service/capture`, transcription uses the configured DSH speech Remote, and synthesis requests the existing same-origin Rabi speech endpoint. A page hide or view close stops recording and playback without cancelling the Session.

Builds require the exact assistant runtime snapshot listed in `sdk-snapshot.json` and a built capture entry from the speech enhancement plugin. Set `DSH_SHARED_ASSISTANT_ROOT` and `DSH_DESKTOP_CAPTURE_ENTRY`, then run `npm run build`. The build verifies every SDK source hash and records the capture artifact hash; the public runtime source is available at https://github.com/vb2250158/shared-assistant-runtime at commit `20321c88d6a93ab29b7d24f09a3f0340dfddb3d6`. Set `DSH_SHARED_ASSISTANT_ROOT` when running `npm test` to run the shared runtime integration cases.

The source and built client have fixture tests only. Installation into an isolated DSH profile, configured preset, live model, real microphone and TTS, and independent authenticated preview have not been verified. The UI keeps unconfirmed input in memory for review, not as a durable crash-recovery receipt. Session output projection currently consumes live chunks; durable-only output and full display acknowledgement remain unverified.

The client bundles `@deepseek-ai/schemastery` because it imports the same local `SettingsSchema` as the Host. The dependency can compile a string `callback` when constructing a schema, but this plugin constructs its schema from static code in `src/settings.mjs`; `readSettings` passes the settings snapshot as data to that already constructed schema. It does not construct a schema from settings values, speech responses, or Session output. This assessment covers this plugin's call path, not other users of the dependency or compromised Host code.
